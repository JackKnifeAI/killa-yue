# Studio instruments and MIDI — 2026-10-17

Stacked on the mastering PR. Project format 8 adds per-track notes, with older projects receiving empty note lanes. The app release version remains 1.4.1.

## Design and usage

Arrange → Piano roll → Add instrument track prepares Killa Pluck or Killa Tines. These are original modal sounds generated by `InstrumentSamples.java`, not recordings of acoustic instruments or third-party soundfonts. The code and generated sounds use the project's Apache-2.0 licence. Samples are written once into the project audio folder and reused; preparation is cancellable.

The piano roll supports draw/move, resize, velocity, exact values, delete, quantise, paging, zoom and saved undo. A gesture previews locally and commits once on release; cancellation discards it. Defaults: quarter-beat grid, 80% velocity, eight visible beats, MIDI pitches 36–84, and up to 4096 notes per track. Note durations follow the tempo map. The two-row keyboard is live audition; notes for the arrangement are drawn in the roll. It does not claim MIDI recording, MIDI-file import/export, pitch bend or aftertouch.

Notes remain editable in the project model. Playback expands them into sample clip references on the existing disk streamer, so track effects, routing, automation, mute/solo, full-mix exports and aligned stems use the same path as audio clips. The plucked samples naturally decay for four seconds; note release is 80 ms. Longer note rectangles do not loop a decaying sample.

The live keyboard feeds Master, with one voice per pitch, 49 bounded read-ahead rings, and a cached 8192-frame attack per key to bridge asynchronous rewinds. The remaining sample stays on disk. File reads, allocation and deletion happen outside the audio callback. No memory, latency or polyphony-performance number is claimed from the phone yet.

USB uses Android MIDI output ports. Bluetooth scans the BLE MIDI service for ten seconds and opens the selected device. The byte-stream decoder handles split packets, running status, realtime bytes, note-on velocity zero, and CC64 sustain; CC120/123 and disconnect release notes. UI delivery is bounded, and backgrounding closes the input. Physical USB/Bluetooth devices remain untested.

API references: [Android MIDI](https://developer.android.com/reference/android/media/midi/package-summary), [Bluetooth permissions](https://developer.android.com/develop/connectivity/bluetooth/bt-permissions). The app still targets API 28, so BLE discovery uses the legacy Bluetooth and foreground location permission path; newer target-SDK handling is separate. No location is read or stored. No background scan is added.
